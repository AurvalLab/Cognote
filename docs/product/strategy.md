# Mnora · 见藏产品战略

- 版本：1.0
- 生效日期：2026-08-14
- 定位：仓库内长期战略权威文档；当前任务状态见 `docs/roadmap/current-plan.md`
- 品牌：公开名称与使用规则见 `docs/product/brand.md`

## 1. 产品命题

> **Mnora is a personal memory system that learns how you see the world.**

Mnora · 见藏是 Local-First 的个人观察与记忆系统。它保存的不是抽象资料库，而是用户与现实世界发生关系的记录：看见的植物、读到的段落、一次旅行、购入的物品或突然出现的想法。

这里的“学习”不是暗中推断人格，而是在用户主动记录、确认、纠错和授权的边界内，逐步形成可追溯、可关闭、可删除的个人记忆理解。当前阶段首先交付可靠记录与找回，长期个性化必须由后续真实需求和隐私验证解锁。

```text
真实观察
→ 本地可靠保存
→ 经授权的 AI 整理
→ 用户确认或纠错
→ 可再次找到与回顾的个人记忆
```

首要假设不是“AI 能否更懂用户”，而是三个可证伪问题：

1. 用户是否愿意持续记录；
2. AI 卡片是否明显优于只保存照片或原文；
3. 用户是否能在需要时快速、可信地找回过去。

任何一项尚未成立时，不用更多 Agent、RAG、图谱或画像掩盖核心价值缺口。

## 2. 首轮用户与价值主张

首轮面向已有主动记录习惯、愿意观察现实世界的个人用户。植物图片是唯一深度领域；纯文字提供原文保真的整理；通用图片只做有明确边界的基础理解。

价值主张：用户能低摩擦地留下观察，得到可信且可编辑的整理结果，并在以后快速找回。

这不是专业鉴定、医疗或食用安全工具，也不是全领域知识问答、社区、电商或自动化助手。

## 3. 不可妥协原则

### 3.1 Local-First

- 无账号、无网络时可创建、编辑、浏览、搜索、删除和恢复本地记录；
- 保存成功只由本地事务决定；
- AI、登录、同步或服务端故障不得导致原始记录丢失；
- 云端 AI、结构化同步和媒体备份是独立授权能力。

### 3.2 用户是记忆的最终权威

```text
Observation + accepted CardVersion + UserCorrection = EffectiveCard
```

用户原文、视觉观察、OCR、外部资料、模型推断和用户纠错必须分存、分来源展示。AI 不覆盖原始观察，也不把推断伪装成事实。

### 3.3 隐私和地域优先

- `private_local` 是不可被授权穿透的本地边界；
- 云端能力按目的授权，敏感内容逐次确认；
- 中国大陆用户的 MVP 数据面位于中国大陆；
- 禁止供应商故障时无感跨境 fallback；
- 派生索引、Embedding、关系和洞察必须可删除、可重建。

### 3.4 确定性 AI Pipeline

MVP 使用固定、可测试、可审计的 Pipeline。LLM 不直接写库，不持有任意工具权限。模型、Prompt、Schema、策略和来源均需版本化。

## 4. 能力阶梯与解锁门

| 能力层 | 用户问题 | 当前承诺 | 解锁下一层的证据 |
|---|---|---|---|
| 可靠记录 | 能否放心留下当下 | 当前阶段 | 离线、重启、强杀不丢数据；生产 UI 可完成闭环 |
| AI 理解 | AI 整理是否值得保留 | 阶段 2 | 卡片保存率、纠错率、隐私与失败恢复达到门槛 |
| 找回与回顾 | 以后能否快速找到 | 本地 FTS 已有，增强能力待验证 | 真实检索问题证明时间线/FTS 不足 |
| 账号与同步 | 能否跨设备而不丢修改 | 阶段 3 | 卡片价值成立且匿名数据归并、冲突模型可验证 |
| 关联与洞察 | 长期记录揭示什么 | 研究项 | 长期留存、用户需求、可解释性与隐私接受度同时成立 |

账号与同步是基础设施演进，不代表已经进入“个人认知”能力。阶段编号表示依赖顺序，不表示必须把整阶段一次性做完。

## 5. 分阶段战略

### 阶段 1：可靠的本地记录

完成生产创建入口、离线与强杀验收、私密能力边界和最小隐私埋点。退出前不扩展云 AI、真实同步、知识图谱、推荐或画像。

### 阶段 2：AI Card MVP

用最小纵向切片验证“本地记录 → 授权 → 上传 → AI 草稿 → 用户确认/纠错”。先做一个可审计的完整闭环，再扩展供应商、路由和卡片类型。

### 阶段 3：账号与同步

在匿名数据无损归并和冲突不静默覆盖的前提下，增加可选账号、多设备同步和媒体备份。同步不能成为阶段 2 卡片价值验证的前置依赖。

### 阶段 4：检索与回顾

只有真实找回需求证明本地 FTS 和时间线不足，才引入服务端 FTS、Embedding、混合召回和带引用问答。

### 阶段 5：关联与个人洞察

仅作为研究方向。不得做黑箱人格画像，不得以“更懂用户”为由扩大采集、上传或跨域使用数据。

## 6. 决策原则

- 优先完成用户可体验的纵向闭环，而不是继续横向铺基础设施；
- 每阶段以真实证据解锁下一阶段，不以代码量或功能数量解锁；
- 先定义失败、删除、撤销和恢复，再定义成功路径；
- 任何新数据采集都必须说明目的、最小字段、保留期限和退出方式；
- 指标门槛见 `docs/quality/mvp-metrics.md`，任务顺序见 `docs/roadmap/current-plan.md`。
