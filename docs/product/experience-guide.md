# Mnora · 见藏产品体验指南

- 版本：1.0
- 生效日期：2026-08-15
- 前身：2026-07-25《Cognote 操作指南》战略草案
- 定位：定义产品体验愿景、渐进式信息架构和界面表达原则

本文吸收早期《Cognote 操作指南》中仍然成立的产品洞察，但不继承其中已经过时的品牌、技术栈锁定、阶段顺序和大而全页面结构。

发生冲突时，长期取舍以 `strategy.md` 为准，可验收行为以 `prd.md` 和 `user-flows.md` 为准，当前任务顺序以 `../roadmap/current-plan.md` 为准。本指南不表示其中描述的未来能力已经实现。

## 1. 体验命题

> 首页展示的不是公共信息流，而是用户最近看见、想到、关心过的世界。

Mnora · 见藏首先帮助用户可靠地留下真实观察，再在明确授权和用户确认的边界内进行整理，最终让记录在需要时重新产生价值。

```text
看见或想到
→ 低摩擦记录
→ 补充“为什么对我重要”
→ 本地可靠保存
→ 可选的 AI 整理与用户确认
→ 找回、回顾或继续探索
```

产品不能退化为图片识别收藏夹，也不能用尚未存在的 AI、图谱或画像装饰空白页面。

## 2. 六条体验原则

### 2.1 用户自己的内容永远是主角

- 首页优先展示真实记录，不展示泛资讯、公共推荐或伪造的示例动态；
- 图片、原文和用户说明在视觉层级上先于 AI 派生内容；
- 没有数据时使用诚实的空状态，引导完成第一条记录，不用空的功能宫格填充页面。

### 2.2 记录必须足够轻

- “记录此刻”是阶段 1 的主要操作；
- 文字与单张图片可以独立完成本地保存；
- 图片说明可以自然记录对象、感受、缘由或想继续了解的问题，不强迫用户先选择分类；
- 保存成功只表示已写入当前设备，不暗示已经上传、同步或完成 AI 分析。

### 2.3 个人意义与客观信息同等重要

一条记录的价值不只在“这是什么”，还在“我为什么注意到它”。界面应允许用户保留：

- 当时看到或想到的内容；
- 为什么想记下；
- 当时的感受或情境；
- 之后想继续了解或处理的事。

阶段 1 可以先使用现有原文或图片说明承载这些内容。没有真实使用证据前，不为了形式完整拆出心情、地点、项目等一组强制结构化字段。

### 2.4 AI 必须可区分、可质疑、可放弃

界面必须区分以下来源：

| 内容 | UI 语义 |
|---|---|
| 用户原文或说明 | “你的记录” |
| 图片中可直接观察的特征 | “从图片中看到” |
| OCR 提取 | “图片文字” |
| 外部资料 | 显示具体来源 |
| 模型推断 | “AI 推测”，同时显示不确定性 |
| 用户纠错 | “你已修正”，优先形成有效结果 |

不使用未经校准的百分比制造精确感；信息不足时明确显示“无法确定”或补拍建议。用户可以接受、修改或放弃草稿，任何操作都不覆盖原始记录。

### 2.5 识别是探索的起点

知识卡片不以“给出名称”结束。随着能力逐步解锁，卡片可以承载：

- 用户还想知道的问题；
- AI 给出的可选补拍或核验建议；
- `待继续`、`已解决` 等轻量后续状态；
- 与既有记录的可解释关联。

这些能力必须由真实需求解锁，不在阶段 1 预建复杂项目系统或知识图谱。

### 2.6 旧记录应在合适的时候回来

“保存”不是终点。找回与回顾分成两个层次：

1. 主动找回：时间线、标签和本地 FTS；
2. 被动回访：每日回顾、历史上的今天或用户主动设置的复习。

被动回访必须可关闭、可解释，并严格排除已删除内容和不允许进入该能力的私密内容。简单的本地回顾不依赖服务端搜索、Embedding 或 RAG。

## 3. 渐进式信息架构

信息架构随真实能力成长。不能先造五个空 Tab，再等待未来功能填满。

### 3.1 阶段 1：可靠记录

核心界面只有用户当前可用的能力：

- 首页/时间线；
- 记录此刻；
- 记录详情；
- 搜索；
- 已删除记录；
- 必要的本地数据说明。

首页以时间线为主体，固定提供清晰的创建入口。搜索、已删除记录和设置可以是次级入口，不要求都占据顶级导航。

### 3.2 阶段 2：AI 卡片

只有真实 AI 纵向闭环可用后，才增加：

- 待处理与失败状态；
- AI 草稿确认；
- 来源、不确定性和纠错；
- 接受后的卡片详情。

“发现”只能展示由用户自己的记录产生且有来源的内容，不能成为通用推荐流。

### 3.3 后续阶段

当数据量和真实行为证明需要时，才逐步解锁：

- 回顾；
- 主题或项目；
- 可解释关联；
- 用户可查看、可编辑、可删除的偏好理解。

知识地图、复杂图谱、情境唤醒和多知识包市场不预留顶级入口。

## 4. 核心页面体验

### 4.1 首页/时间线

首页回答三个问题：

1. 我最近记录了什么；
2. 我现在如何继续记录；
3. 是否有一条真实旧记录值得重新看见。

阶段 1 的最低要求：

- “记录此刻”在首屏可发现；
- 记录卡片以内容、时间和本地状态为主；
- 空、加载、错误、无搜索结果和已删除状态都有明确设计；
- 不出现不可用的 AI、同步、私密、项目或画像入口。

### 4.2 创建记录

- 文字模式提供开放提示，例如“记下你看到、想到，或为什么想留下它”；
- 图片模式先展示用户选中的图片，再提供可选说明；
- 保存中的返回、重复提交、文件错误和本地空间不足有确定行为；
- 成功反馈使用“已保存在此设备”，避免模糊的“已完成”。

### 4.3 记录详情

详情先展示原始记录，再展示状态和可用操作。阶段 2 增加 AI 内容时，原始记录与 AI 卡片不得合并成一段无法辨别来源的文字。

### 4.4 AI 草稿与卡片

卡片采用四层结构，而不是一个模型自由生成的大文本块：

1. 原始观察；
2. 用户语境与个人意义；
3. AI 整理、事实来源与不确定性；
4. 用户确认、纠错和可选后续。

### 4.5 搜索与回顾

搜索结果显示命中片段和内容类型，不声称理解用户意图。未来问答必须引用来源；未来回顾必须说明“为什么现在出现这条记录”。

## 5. 视觉与交互方向

视觉气质应当安静、温暖、可信、有观察感，不做企业后台，也不做夸张的 AI 科幻界面。

- 内容优先：真实图片和文字承担主要视觉重量；
- 层级克制：少量稳定的字号、间距、圆角和颜色 token；
- 状态清晰：本地、处理中、失败、待确认、已修正有一致表达；
- 动效有因：只解释保存、展开、状态变化和页面关系，不用动效掩盖空内容；
- 可访问：正文、辅助文字、错误状态和点击区域满足可读性与触控要求；
- 能力诚实：未实现功能不以灰色按钮、空 Tab 或“敬请期待”长期占位。

CNG-111A 应先产出关键页面高保真方案和状态矩阵，再进入全局视觉实现；视觉方向必须在真实 Android 尺寸和真实内容长度下评审。

## 6. 早期指南取舍

| 早期设想 | 当前结论 |
|---|---|
| “今天发现了什么”首页 | 保留为首页体验命题，不照搬模块堆叠 |
| 图片、文字记录 | 当前核心能力 |
| 语音、Share Sheet | 延后；核心记录可靠后优先评估 Share Sheet 的降摩擦价值 |
| 四层知识卡片 | 保留，并强化来源、纠错与个人语境 |
| 自然语言搜索 | 延后到真实检索问题证明本地 FTS 不足 |
| 每日回顾、历史上的今天 | 保留；可先做本地、可关闭的小实验 |
| 偏好画像 | 研究项；只能透明、可解释、可编辑、可删除 |
| 探索任务、项目 | 延后到真实后续需求成立 |
| 主题知识包 | 作为未来 Schema/评测扩展方式，不做早期市场 |
| 数据导出、撤销授权、删除 AI 派生数据 | 保留为数据所有权能力，按隐私与同步阶段实施 |
| 单卡私密空间 | 原意保留，但升级为独立加密存储硬边界；实现前不暴露入口 |
| 五个顶级 Tab | 放弃固定结构，采用渐进式信息架构 |
| 登录、后端和同步前置 | 放弃；继续坚持 Local-First 和分阶段授权 |
| 多运行时 Agent | 放弃；继续使用确定性、可审计 Pipeline |

## 7. 体验验证门槛

界面完成不以“页面都画了”为准。至少验证：

- 新用户能否理解产品保存的是什么；
- 能否无指导完成第一条文字和图片记录；
- 是否理解“已保存在本地”和“已由 AI 分析”的区别；
- 能否找到并重新打开旧记录；
- 能否辨别用户内容、事实来源和 AI 推断；
- 能否发现并完成纠错；
- 空状态、长文字、失败、离线和无图片数据时是否仍然成立。

具体指标使用 `../quality/mvp-metrics.md`，不得用主观“更高级”“更像成品”替代可用性证据。
